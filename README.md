# Тестовое Neowise. AI-помощник для входящих заявок

Ориентир — 45–60 минут. Менеджер вводит текст заявки, получает тему и черновик ответа. Он читает результат и сам решает, что отправить клиенту.

## Запуск

В репозитории есть сервер, HTML-страница и имитатор модели. Нужен Node.js 20 или новее. Зависимостей и ключей нет.

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. Порт можно задать через переменную `PORT`.

## Тесты

```sh
node --test
```

Или `npm test`. Тесты сами поднимают сервер на свободном порту и проверяют, что:

- метки `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` и зависшая модель дают `manual_review` быстрее 1 с, хотя имитатор на `[timeout]` ждёт 1,2 с; зависшей модели сервер даёт 300 мс и посылает ей сигнал отмены;
- черновик модели из одних невидимых или управляющих символов даёт `manual_review`;
- пустой, отсутствующий, нестроковый ввод, текст из одних невидимых или управляющих символов и битый JSON дают 400 `invalid_input`, а модель при этом не вызывается;
- тело больше 64 КБ даёт 413 `too_large`;
- оборванный клиентом запрос пишется в лог ошибок, а сервер продолжает работать;
- корректный ответ даёт `ready` только с полями `status`, `topic`, `draft`.

## Как устроено

- `triage.mjs`: проверка ввода (`parseTriageInput`), вызов модели с лимитом 300 мс (`callModel`), проверка ответа модели (`parseModelOutput`).
- `app.mjs`: HTTP-маршруты и лимит тела запроса в 64 КБ. `server.mjs` только запускает сервер.
- `index.html`: старый черновик убирается перед каждым запросом, при любом сбое и при любой правке текста заявки. Ответ на запрос по уже изменённому тексту не показывается. Ответ модели выводится только через `textContent`.
- При `manual_review` страница показывает общее сообщение о ручном разборе. Сбои по дороге до модели она называет отдельно: нет связи с сервером, сервер не ответил за 5 с, ошибка сервера (ответ 5xx), неожиданный ответ.
- Ошибки, из-за которых сервер отвечает 500, пишутся в лог.

## Что изменить

1. Доработайте `POST /api/triage`. Принимайте JSON с полем `text`, содержащим непустую строку. При пустом, отсутствующем, нестроковом вводе или битом JSON верните HTTP 400 и `{"status":"invalid_input"}`.
2. При корректном ответе модели верните HTTP 200 и `{"status":"ready","topic":"…","draft":"…"}`. Допустимые темы — `delivery`, `pricing`, `other`. Черновик должен быть непустой строкой. При таймауте, ошибке модели или неподходящем ответе верните HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`. Ограничьте ожидание модели 300 мс. Оставьте поведение выданного имитатора прежним.
3. Покажите на странице тему и черновик при успехе. Для `manual_review` покажите понятное сообщение менеджеру и очистите предыдущий черновик. Добавьте хотя бы один исполнимый тест для поведения при сбое и инструкцию его запуска.

Для локальной проверки имитатор принимает любой обычный текст. Метки `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` включают отдельные сценарии сбоя.
